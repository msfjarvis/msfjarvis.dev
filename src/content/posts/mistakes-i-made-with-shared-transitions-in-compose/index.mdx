Shared Element Transitions: You've never seen 'em. Only somewhat kidding, since I can't remember the last time I saw one in a format that was not a Google-authored Android sample app. They used to be pretty finicky as a platform feature and didn't work consistently, plus they seem to have relied on Fragments so it probably is no surprise nobody wanted anything to do with it.

So, here's a quick explainer: when moving between Screen A to Screen B in an app, you will sometimes have one or many UI elements that are shared. For example, clicking a restaurant in a list and then going to its menu will probably show the name in both places. With Shared Element Transitions, you can have the name from Screen A animate into the one in Screen B in a (usually) smooth transition animation. Here is the laggy video Google plays at the top of the relevant docs page.

We're in business! The transition works, but doesn't _look_ that great yet. Turns out, the answer to it was to simply read the name of the feature again. Shared **Element** Transitions, not Shared **Container** Transitions. I had scoped the animation to animate from the `LobstersCard` component to the `PostHeader` component which the framework was doing correctly, but it'd look nicer for it to be individual elements. With [that change in place](https://msfjarvis.dev/g/compose-lobsters/7f129f13beca), this is what we get.

It's not immediately obvious in the example but each tag such as `elixir` or `erlang` is animating individually here. This will now cause problems :D

The first issue I noticed was that if the same post was in both the "Hottest" and "Newest" feeds, they would animate when moving between the two! I wish I had a recording to attach here but [scrcpy](https://github.com/Genymobile/scrcpy) is having trouble rendering that transition. This was fixed by giving each list of posts [its own transition scope](https://msfjarvis.dev/g/compose-lobsters/801f4cd57a91) so they behave more like islands.

Another issue I noticed was that some tag pills were not being sized correctly if I scrolled far enough for the layout to be reused. This was fixed by animating the entire `TagRow` parent instead of individual `Tag`s. Shared container _can_ be the right choice, at the correct granularity!
