Shared Element Transitions: You've never seen 'em. Only somewhat kidding, since I can't remember the last time I saw one in a format that was not a Google-authored Android sample app. They used to be pretty finicky as a platform feature and didn't work consistently, plus they seem to have relied on Fragments so it probably is no surprise nobody wanted anything to do with it.

So, here's a quick explainer: when moving between Screen A to Screen B in an app, you will sometimes have one or many UI elements that are shared. For example, clicking a restaurant in a list and then going to its menu will probably show the name in both places. With Shared Element Transitions, you can have the name from Screen A animate into the one in Screen B in a (usually) smooth transition animation. Now that we're familiarised, let's walk through the multiple iteration it took for me to get this right in **Compose**, which already makes it significantly easier.

Following the [official docs](https://developer.android.com/develop/ui/compose/animation/shared-elements), I did my first naive implementation in [this commit](https://msfjarvis.dev/g/compose-lobsters/1941fc6609ae) and the results were rather disappointing.

This turned out to be [a bug](https://issuetracker.google.com/issues/585614999) in the underlying Navigation3 library which was relatively easy to isolate since I use the latest alpha releases of Jetpack and remembered seeing some transition related changes in the release notes. Downgrading from [Navigation3 1.3.0-alpha04 to 1.2.0](https://msfjarvis.dev/g/compose-lobsters/3438f8a3ea52) resolved the bug and now it looks like this.

We're in business! The transition works, but doesn't _look_ that great yet. Turns out, the answer to it was to simply read the name of the feature again. Shared **Element** Transitions, not Shared **Container** Transitions. I had scoped the animation to animate from the `LobstersCard` component to the `PostHeader` component which the framework was doing correctly, but it'd look nicer for it to be individual elements. With [that change in place](https://msfjarvis.dev/g/compose-lobsters/7f129f13beca), this is what we get.

It's not immediately obvious in the example but each tag such as `elixir` or `erlang` is animating individually here. This will now cause problems :D

The first issue I noticed was that if the same post was in both the "Hottest" and "Newest" feeds, they would animate when moving between the two! I wish I had a recording to attach here but [scrcpy](https://github.com/Genymobile/scrcpy) is having trouble rendering that transition. This was fixed by giving each list of posts [its own transition scope](https://msfjarvis.dev/g/compose-lobsters/801f4cd57a91) so they behave more like islands.

Another issue I noticed was that some tag pills were not being sized correctly if I scrolled far enough for the layout to be reused.

<Figure src={weird_pills} small={true} />

I don't know what the root cause of this issue was, but on a hunch I changed the tags to transition the full row instead of each individual one and that seems to have fixed it.
