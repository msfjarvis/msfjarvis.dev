# Personal Projects

I threw GPT-5.6 Sol at max thinking on [Claw](https://github.com/msfjarvis/compose-lobsters) with a prompt to identify opportunities to improve query performance, push operations down from Kotlin to SQLite, and any other improvements that have become available in the year or so since I last had an LLM audit my miniscule amount of SQL. I mostly do this to find out SQLite features, and got to learn about a few more tricks.

- `INSERT OR REPLACE` can accidentally trigger cascading deletions via foreign key relations, so it is better spelled out using `ON CONFLICT(primaryKey) DO UPDATE SET column1 = new.column1;`
- Specifying `WITHOUT ROWID` when creating a table skips a hidden column that SQLite uses as a more efficient primary key for searching for the row in the storage engine. This can yield modest storage savings for bigger data sets. More on that [here](https://sqlite.org/rowidtable.html).
- Use `RETURNING <field>` to have a query both update and return data, which can be used to avoid an additional query to read back the updated data.

## CLANK CLANK CLANK

This week I changed my [Pi](https://pi.dev) setup to ditch the third-party subagent extension and instead go back to the barebones example subagent extension from the main Pi repo. I updated it to [handle some more of my local tools](https://git.msfjarvis.dev/msfjarvis/my-pi/commit/fece2293c9795924229ceac59e09ffce884cf696), and added a config option to [limit nested subagents](https://git.msfjarvis.dev/msfjarvis/my-pi/commit/bc026882d549c4586d9548657c401534408bb81a) which was a problem that I had seen with GPT-5.6 models which recursively spawned subagents and racked up massive bills.

I also finally managed to make the `websearch` tool from [tau](https://github.com/goncalossilva/tau) work on my setup. I hadn't realized that [llm-agents.nix](https://github.com/numtide/llm-agents.nix) bundles Pi with the Bun JS runtime which didn't have the necessary `node:sqlite` module. Switching that to Node.js solved the problem for me.
