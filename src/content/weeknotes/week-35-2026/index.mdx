## Meta

While tinkering around with the site I noticed that the RSS feeds take a little _too_ long to generate and actually register as slow in Astro's build output, so went over it with a fine tooth comb and implemented some small changes that sped up the feed generation by nearly 2x. [Caching](https://github.com/msfjarvis/msfjarvis.dev/commit/4521d04a179a39ae96926055b9960da6b1f00d1a) the [AstroContainer](https://docs.astro.build/en/reference/container-reference/) object used to render individual feed entries as HTML so that it does not get re-rendered for each format gave the biggest win, and I figured while I was at it I'd also opt into Astro's experimental [build caching](https://github.com/msfjarvis/msfjarvis.dev/commit/4c158e6c19f4545375227a1c2cec6d51708d0fda).

## 🤖 CLANK CLANK CLANK

I spent some time making the [Pi](https://pi.dev) set up more portable and making it easier to hack on with code completion and what not. The trick for it is creating an NPM package at `~/.pi/agent` and then loading all the other extensions as workspaces which centralises `node_modules` and gets you dependencies even for the single-file extensions.

I improved the MCP extension to [immediately load the UI](https://git.msfjarvis.dev/msfjarvis/my-pi/commit/d721fd17ae0a4f7cc9f662e1d5e4ae651ad1f8cb) and refresh authentication status in the background to improve the user-facing interaction, and implemented a [command-driven model switcher](https://git.msfjarvis.dev/msfjarvis/my-pi/commit/1a1cf169b2579a057e777f53169233b53b765079) so I can quickly swap models by running `/sol` or `/claude`.
